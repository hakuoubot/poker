# poker — テキサスホールデム アクションアドバイザー

自分の2枚と場のカードを入れると、**フォールド / コール / レイズ**(または
チェック / ベット)を期待値の高い順に並べて教えてくれるツール。

同じリポジトリ群にある麻雀の打牌アドバイザー(`ma-jyan`)のポーカー版。
考え方は同じで、

- 麻雀: 受け入れの広さと放銃の危険度 → **切る牌**を優先度順に
- ポーカー: 勝率(エクイティ)とポットオッズ → **アクション**を優先度順に

**外部への通信は一切しない。** 勝率計算もハンド評価もすべて自前・ローカル完結で、
必要なのは Python 本体だけ(追加ライブラリなし)。

**ポーカーチェイスのランク戦(6人ターボトーナメント)に対応。**
順位ポイントの期待値(ICM)で判断するモードがあり、
浅いスタックのオールイン判断も出せる。キャッシュゲームとして使うこともできる。
金額・スタックはすべて BB 単位。

> 対局中に外部ツールを使うのは各サービスの規約に触れる可能性が高い。
> 画面読み取りや自動操作は作らない方針で、**対局後の検討・復習用**という前提。

## 使い方

### GUI

```
python app.py
```

または `ポーカーアドバイザーを起動.bat` をダブルクリック。

1. 下のパレットからカードをクリックすると、左上のスロットに順番に入る
   (自分の手札2枚 → フロップ3枚 → ターン → リバー)。
2. スロットをクリックするとそこに入力先が移る。右クリックで1枚消える。
3. 「状況」にポット・自分が払う額・残りスタックを BB 単位で入れる。
   誰もベットしていない場面なら「払う額」を 0 にする。
4. 入力を変えるたびに自動で計算し直す。重い局面は右上のバーで進み具合が出る。

### CLI

```
python advisor.py
```

対話式。カードは `AsKd` のように英字で入力する
(`s`=スペード `h`=ハート `d`=ダイヤ `c`=クラブ、10 は `T` でも `10` でも可)。

### よく出る局面を先に解いておく

```
python precompute.py --list      何をどれだけ解くか見る
python precompute.py             代表フロップを全部解いて貯める
```

フロップは1局面80秒前後かかるので、**寝ている間に解かせておく**ための道具。
解いた結果は保存され、次からは即答になる。途中で止めても解けた分は残り、
もう一度走らせると続きから進む。

フロップは 22100 通りあって全部は解けないので、
テクスチャ(手触り)ごとの代表フロップだけを解く。
自分がよく負けるボードが決まっているなら、
`precompute.py` の `REPRESENTATIVE_FLOPS` をそれに書き換える方が効く。

### 検証

```
python test_evaluator.py    ハンド評価器の検証
python test_equity.py       勝率計算の検証
python test_icm.py          順位期待値(ICM)の検証
```

`test_evaluator.py` は素朴な総当たり実装と2万局面つき合わせる。
`test_equity.py` はモンテカルロと全数え上げを同じ局面で比べ、さらに
プリフロップの勝率を公表値と比べる。どちらも最後に `OK` が出れば通っている。

## 何を見て判断しているか

| 出るもの | 中身 |
| --- | --- |
| 勝率 | ショーダウンまで行ったときに勝つ確率。引き分けの分割も込み |
| 必要勝率 | ポットオッズから決まる、コールが損しないための最低ライン |
| アウツ | 次の1枚で役が上がるカードの枚数と内訳 |
| アクションの期待値 | 降りるを 0 として、各アクションが何BB増えるか |
| レンジ表の推奨 | プリフロップのみ。6-max の標準的なチャートによる推奨 |
| 順位EV(pt) | トーナメントモード時。順位ポイントで見た期待値。**これが判断の基準** |
| 順位確率 | 今のスタック構成で1位〜6位になる確率 |
| ICM込みの必要勝率 | 順位を守るぶん、チップ基準より高くなる |
| オールイン判断 | プリフロップで25BB以下のとき、押すか降りるかを順位EVで |
| 相手の前の行動 | 「コールしてきた」「打ってきた」を選ぶとレンジが絞られ、勝率が変わる |

期待値の式は `strategy.py` の冒頭に全部書いてある。ざっくり言うと

- コール: `勝率 x ポット - 負ける確率 x 払う額`
- レイズ: `相手が降りる確率 x ポット + 降りなかった場合の期待値`

で、「相手が降りる確率」は MDF(相手がセオリー通りに守る場合の頻度)から出し、
「降りずに付いてきたときの勝率」は相手のレンジのうち **今のボードで強い方** だけが
残ると考えて計算し直している。

## 構成

### 判断ロジック(完成・検証済み)

- `cards.py` — 52枚のカードを 0〜51 の整数で表す。入力文字列のパース。
- `evaluator.py` — 5〜7枚から役の強さを整数で返す評価器。
  21通りの総当たりではなく、ランクの出現数とスートのビットマスクから直接判定する。
  実測で1秒あたり十数万〜30万回。
- `equity.py` — 勝率の計算。組み合わせが少ない局面(リバー、ターン+相手1人)は
  **全数え上げで正確に**、それ以外はモンテカルロ。相手のレンジ指定にも対応。
- `draws.py` — 今の役とアウツ。場のカードだけで作れる役は除いて数える
  (ボードがペアになっただけのカードはアウツに入らない)。
- `preflop.py` — 6-max のオープンレンジ/3ベット/コールのレンジ表と、
  `22+, ATs+, KQo` のような表記を展開するパーサ。
- `icm.py` — 順位期待値。今のスタック構成から順位確率を出し、
  順位ポイントに換算する(Malmuth-Harville)。**トーナメント対応の中心**。
  複数人が絡むポットのチップの動きにも対応している。
- `pushfold.py` — 浅いスタックでオールインするか降りるか。
  相手のコールレンジを想定して、順位EVで比べる。
- `calibrate.py` — ソルバーの戦略に従って手を打ち回し、実現率を実測する。
  ポジションがある側は素の勝率以上に取る(IP 1.26 / OOP 0.79)ことが分かった。
  ただし**レンジ表の較正には使えなかった**(理由は HANDOFF 追記6)。
- `ranges_gen.py` — **今のスタックの深さに合わせたプリフロップのレンジ表を作る。**
  169ハンドそれぞれを「降りる/2.2BBにレイズ/オールイン」で比べて表にする。
  キャッシュ用チャートが合わない 25〜40BB 帯のためのもの。
- `strategy.py` — 上記をまとめてアクションを期待値順に並べる。

### 画面

- `app.py` — tkinter の GUI。カードのクリック入力、自動再計算、
  計算は別スレッドなので入力中に固まらない。
- `advisor.py` — 対話式CLI。

### GTOソルバー(任意)

- `solver_engine/solver_bridge.py` — TexasSolver との橋渡し。
  GUI の「ソルバーに聞く」ボタンから、その局面の**本物のGTO戦略**
  (チェック何%・ベット何%…)を出せる。
  ソルバー本体は別途置く(`solver_engine/README.md`)。無くてもアプリは動く。
  実測でターン7秒・リバー数秒・**フロップ82秒**。フロップは検討用。
  **一度解いた結果は保存され、同じ設定なら即答になる**(22.5秒 → 0.03秒)。
  ソルバーの解は自分の手札に依存しないので、
  **手札だけ変えた場合も保存した結果を使い回せる**。

### 検証

- `test_evaluator.py`, `test_equity.py`, `test_icm.py`

## トーナメント(ポーカーチェイス)として使うとき

画面左下の「順位ポイントで判断する」を入れると、期待値が **チップ(BB)から
順位ポイント(pt)に切り替わる**。判断の並び順も順位EVで決まる。

- 順位ポイントは STAGE V の実測値 `1位 +35 / 2位 +21 / 3位 +7 / 4位 -6 /
  5位 -19 / 6位 -28` が既定。他のプリセットも選べる。
- 自分以外のスタックを入れると順位確率が変わり、判断も変わる。
- **降りても1周ぶんのブラインドとアンティは失う**ことを織り込んでいる。
  ターボはこれが効くので、入れないと降りる判断が甘く出る。
  アンティ0.1BB・6人なら1周 2.1BB。
- 「このスタックのレンジ表を作る」で、**今の状況専用のオープンレンジ表**を
  169マスで作れる(1〜2分)。キャッシュ用チャートとのズレも一緒に出る。
- 効果の例(10BB・BTN からのオールイン):

| ハンド | チップ基準 | 順位ポイント基準 |
| --- | --- | --- |
| KTo | オールイン (+0.63BB) | **降りる (-0.59pt)** |
| QJs | オールイン (+0.95BB) | **降りる (-0.19pt)** |
| 87s | オールイン (+0.58BB) | **降りる (-0.66pt)** |
| A5s | オールイン (+1.24BB) | オールイン(僅差) (+0.17pt) |

チップだけ見ていると押しすぎる、というのがランク戦で一番ポイントを失う形。
その差がそのまま数字で出る。

## 分かっている制限

- **以降のストリートのベットを考えていない。** インプライドオッズ
  (完成したときに余分に取れる分)が入っていないので、ドローハンドの期待値は
  実際よりやや低めに出る。
- **相手のレンジはポジションのオープンレンジで固定。** フロップ以降で相手が
  どこまで絞られたかは追っていない。
- **大きいベットの評価は甘め。** 相手が MDF 通りに降りる前提なので、
  オールインの期待値が実戦より高く出やすい。画面にも毎回その注意を出している。
- **複数人相手は近似。** 全員が同じレンジ・同じ確率で降りるとみなしている。
  順位EVのチップの動きは人数ぶん正しく計算するが、
  自分が負けたとき誰が取るかは均等とみなしている。
- **ICM は実力差もブラインドの上がり方も見ていない。** チップ量の比だけで
  順位確率を出すモデル(Malmuth-Harville)。
- **オールイン判断はコールが1人までの近似。** 2人以上に囲まれる分は無視しており、
  そのぶんオールインの評価が少し甘い。
- レンジ表は GTO ソルバーの出力そのものではなく、広く出回っている
  6-max の標準的なチャートに合わせた形。混合戦略(同じ手を50%レイズ)は無い。
  **ソルバーを入れればその局面だけは本物の混合戦略が見られる**が、
  ソルバー側もポストフロップ専用・2人用で、レンジはポジション任せ。

設計の経緯・迷ったところ・数字の根拠は `HANDOFF.md` に時系列で書いてある。
